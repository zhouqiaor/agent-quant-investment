# SPEC：第3轮迭代——回测可视化 & 持仓K线图

> 本轮目标：把"有数据但看不见"的价值释放出来。真实日K线、全量股票目录已就位，
> 用最小成本把回测结果从"数字"升级为"可解读的图表"，把持仓详情从"文字"升级为"一眼看懂的K线"。

---

## 一、为什么做这一步（价值判断）

| 维度 | 现状 | 问题 | 本轮后 |
|---|---|---|---|
| 回测结果 | 总收益率、最大回撤、胜率 3 个数字 | 用户看不到过程，无法判断策略质量 | 收益曲线 + 回撤曲线 + 交易标记，可解读 |
| 持仓详情 | 成本/现价/浮盈 文字 | 没有价格走势参考，买入卖出缺乏依据 | 真实日K线 + 成本线 + 买卖点标记 |
| 策略可信度 | 黑箱 | 收益从哪来、什么时候赚什么时候亏，全靠猜 | 每笔交易在曲线上可见，逻辑可追溯 |

**为什么不是策略编辑器/选股器**：
- 编辑器工作量大（拖拽、条件组合、即时预览），属于 P2
- 选股器依赖指标体系，尚未有数据基础
- 回测+K线 复用已有的真实K线 API + 回测引擎，增量成本最低，体验提升最大

## 二、范围界定

### In Scope（本轮交付）

1. **回测结果可视化**
   - 收益曲线（累计净值 vs 基准）
   - 最大回撤曲线
   - 交易标记（买入点/卖出点在曲线上标注）
   - 关键指标卡片（收益率/年化/夏普/最大回撤/胜率/盈亏比）

2. **持仓详情K线图**
   - 真实日K线（30/60/120 日切换）
   - 成本价参考线
   - 买入/卖出交易标记（如有历史）
   - 当前价标注

3. **回测引擎补充字段**
   - 每日净值序列（dailyEquity）
   - 交易明细序列（带时间戳的买卖点）
   - 基准收益（沪深300对比，如无则省略，不阻塞）

### Out of Scope（本轮不做）

- 分钟级K线、实时分时图 → 数据源不支持
- 技术指标（MACD/BOLL 等） → P2 以后
- 拖拽式策略编辑器 → P2
- 多策略对比回测 → P2
- 选股器/条件选股 → P2

## 三、技术方案

### 3.1 图表选型（最小成本原则）

**方案对比**：

| 方案 | 小程序兼容 | 包体积 | 开发成本 | 结论 |
|---|---|---|---|---|
| echarts-for-taro / taro-echarts | 需 canvas 适配 | ~500KB | 中 | 备选（功能全但重） |
| @antv/f2（蚂蚁 F2） | 有 taro 适配 | ~150KB | 中低 | 备选（移动端专用） |
| 自研 SVG 折线图（Tailwind + div/SVG） | H5 完美，小程序 SVG 有限支持 | ~0 | 低 | ✅ 首选 |

**决策**：先用 Tailwind + SVG 手搓折线/柱状/散点图（~150 行一个组件）。
- 回测收益曲线：一条 SVG 路径 + 填充渐变，够了
- K线：SVG 矩形（实体）+ 竖线（影线），~30 根足够
- 交易标记：SVG 圆点 + 箭头

理由：
1. 包体积 0 增长，符合小程序性能要求
2. Tailwind 直接上色，与现有设计系统一致
3. 未来如果要换 echarts，数据结构不变，只换渲染层

### 3.2 数据结构（后端增量）

**回测接口增量字段**（`/api/backtest/run` 响应）：

```ts
interface BacktestResult {
  totalReturn: number       // 已有
  maxDrawdown: number       // 已有
  winRate: number           // 已有
  // 新增：
  dailyEquity: { date: string; equity: number; benchmark?: number }[]
  trades: BacktestTrade[]   // 已有，但需补日期字段
  annualizedReturn: number
  sharpeRatio: number
  profitFactor: number      // 盈亏比
  totalTrades: number
}
```

**持仓K线**：复用现有 `/api/stock/kline`，无需后端改动。
前端按 symbol 请求，注入成本线和交易点。

## 七、风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 小程序端 SVG 支持有限 | 图表在微信/抖音小程序渲染异常 | 用 @tarojs/components 的 Canvas 替代？不，先测 H5，小程序端如异常再降级为图片或文字 |
| K线数据量大导致渲染卡 | 120 根K线 SVG 节点多 | 限制默认 30 根，切换时再加载更多；SVG 用 path 合并影线 |
| 回测日净值计算误差 | 曲线与最终收益对不上 | TDD 严格校验：dailyEquity 末值 = 最终总资产 |
